# 主页与网页对照 Demo 审核说明

日期：2026-10-08。交付阶段：前端交互 Demo，等待用户审核。

2026-10-09 更新：本文件为上一阶段的历史验收记录；同页 Demo 已迁至 `/web/demo`，`/web` 现在是实际网页翻译 MVP，见 [当前说明](web-mvp.md)。

## 本次范围

设计判断：这是沿用现有品牌的产品入口优化，采用现有原生 CSS 与系统字体，不引入新的 UI 设计系统。设计变化/动效/密度按 4/4/4 控制；动效用于入口反馈和状态变化。

- 首页 `/`：保留米白底、深绿色、T 标识与原有中文文案语气；新增 PDF 和网页两个入口，支持鼠标、键盘和浏览器历史导航。
- PDF `/pdf`：承接原有上传和翻译流程；已有 `/tasks/{id}?page=n` 地址保持可用，翻译新文档返回 `/pdf`。
- 网页 `/web`：三个内置示例，两侧渲染相同英文内容；明确标注未执行翻译。
- 两侧支持滚动联动、共享缩放、标签切换、折叠、搜索筛选、收藏状态和悬浮反馈。关闭滚动联动不拆分其他页面状态。
- 浅色/深色模式、减少动画偏好和窄屏适配。手机宽度下主页收起装饰预览以同时展示两个入口；对照页面改为上下排列。

这次使用同一个 React 状态驱动两个示例组件。没有接入 Chromium、rrweb、第三方网页抓取或翻译模型，因此不构成上一份技术设计中的浏览器镜像可行性验证，也不能由此推断任意网站兼容性。

## 如何审核

运行 `npm run dev`，打开 `http://127.0.0.1:5173/`。首页和网页 Demo 不依赖 Python 后端；真实 PDF 翻译仍需按 README 启动和配置后端。

1. 在首页进入 PDF，再通过顶部导航进入网页，或返回首页。
2. 在任一侧滚动，检查另一侧是否跟随；关闭联动单独查阅，再开启，检查是否跟随最后操作的一侧。
3. 调整顶部 50%–200% 缩放，检查两边字体、组件大小和阅读位置；可重置到 100%。Ctrl/Cmd + 滚轮也已接入视图缩放。
4. 分别从左右切换 Overview / Details / Resources，展开问题，点击 Save，在 Find a section 中输入 `context`。
5. 切换文档/文章/产品示例，使用浏览器后退/前进，并刷新当前地址。
6. 输入普通外部网址，检查演示范围提示。它不会偷偷替换成另一个示例或请求该网站。
7. 检查浅色、深色及窄屏布局。

## 验证记录

- `npm run check`：TypeScript 与生产构建、现有 3 项前端测试通过。
- 浏览器实际操作：左侧切标签与右侧切标签均使两边 `aria-selected=true`；右侧展开问题使两边 `aria-expanded=true`。
- 右侧搜索 `context` 后，两侧输入值一致，各保留一个匹配内容块；右侧收藏后，两侧均显示 Saved。
- 左侧连续翻滚后，两个视图的 `scrollTop` 均为 940，最大滚动值均为 1025。关闭联动后为 `[940, 0]`，重新开启后跟随右侧成为 `[0, 0]`。这些值来自当次布局，不是固定的产品参数。
- 选择 150% 后，两侧显示容器的倍率均为 1.5。
- 外部网址显示「当前 Demo 仅支持下方三个内置示例。真实网址加载将在审核后接入。」
- 示例历史导航已验证：前进/后退后，URL、当前示例与左右标题一致。
- 已在 1440×900 桌面、390×844 手机宽度和默认浏览器宽度检查布局；390px 下页面无水平溢出。浅色/深色均已查看。
- PDF 入口和原有上传界面已检查；本轮未启动真实模型翻译或新建 PDF 任务。Ctrl/Cmd + 滚轮未做自动化输入验收。
- 本机生产预览的 Lighthouse 桌面单次检查：主页性能/无障碍/最佳实践为 100/100/100；网页 Demo 无障碍/最佳实践为 100/100。主页 LCP 约 0.3 秒、CLS 为 0。这是本地样例检查，不代表部署后或真实第三方网页的性能。
- 1280×720 短屏下，Demo 整页高度为 720px，阅读区在内部滚动；没有整页水平溢出。
